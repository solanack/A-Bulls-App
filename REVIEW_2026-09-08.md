# A Bulls App release review — 2026-09-08

## Baseline and product direction

GitHub `main` is the only release baseline. The existing minimal Field interface and native Three.js/WebGL renderer remain the product foundation. The release stays read-only: no wallet connection, ownership proof, signing, swaps, copy trading, token creation, liquidity actions, custody, Bull Invaders, LIFE mode, missions, or scores.

The approved living-universe taxonomy is now explicit and enforced:

- **Galaxy** = launch ecosystem / launchpad.
- **Planet** = token / mint.
- **Star** = observed public wallet / holder / trader.
- **Asteroid belt** = observed liquidity / LP depth.
- **Comet** = indexed current or recent trade.
- **Black hole / supernova / wormhole / ghost** require the corresponding retained collapse, historical, migration, or dormant evidence.
- **Dust** is decorative only and is never certified market evidence.

Legacy producer contracts that used the old star/planet labels remain compatible only behind adapters. They are normalized before rendering and before Grey speech.

## Research-layer work completed

### Token planet systems

A real token planet is now navigable. Selecting it enters a local planetary system without replacing the renderer or issuing a passive provider lookup. The selected token stays central. Retained positive-net public-wallet observations become wallet **STARS** around it, retained recent trades become **COMETS**, and an **ASTEROID BELT** appears only when observed liquidity is available.

The holder-star endpoint reads the existing Intelligence D1 tables only. Its displayed share is explicitly the share of the retained positive-net sample, not percent of total token supply. If holder evidence is missing, the sky remains honestly empty instead of inventing wallets or spending provider credits. Robinhood/PONS tokens currently return an honest empty holder sky because wallet-star membership is not yet retained for that chain.

Planet entry narration is now also local to the retained snapshot; entering a planet does not silently invoke the live QUERY/provider path. A deliberate later interaction with the central planet can still request its normal market investigation. Focusing a wallet STAR prefills its public address into the research query field so the wallet can be investigated without implying identity or ownership.

### Weekly Top 50 Trader Observatory

The hamburger menu includes a separate **TOP 50 TRADERS** research destination. The Intelligence Worker builds a bounded seven-day ranking from retained indexed Solana trades and caches it in the existing Intelligence D1 cache. It does not scrape or depend on an undocumented Fomo leaderboard API.

The ranking uses realized SOL only where an in-window sell can be matched to in-window acquired inventory using an average-cost method. Unmatched sells are excluded rather than assigned an invented basis. Input is bounded to the most recent 50,000 retained rows from the selected retained trade source; the payload reports the source, rows read, row cap, and whether that cap may have truncated older in-window trades. The view reports its observed window, method, and sample limitation and explicitly says it is not a skill score, identity claim, recommendation, or copy-trading instruction. Fomo is retained only as a reference-only concept and is marked `ingested: false`.

### Watchlist v2

The device watchlist now stores both token **PLANETS** and public-wallet **STARS** with distinct identities. Existing token-only v1 watchlists migrate forward. A saved item remains a research reference; it is not silently promoted into fresh evidence. The Watchlist view reuses current indexed Field evidence when available and otherwise keeps the saved object visibly reference-only.

### PONS taxonomy repair

PONS ranked tokens and the pinned PONS teaching token now render as token **PLANETS**, matching Solana/Pump and the approved taxonomy. Origin verification, market-cap ranking rules, the $500,000 floor, and the two-cycle membership rules remain unchanged.

## Existing research and safety behavior preserved

- Replay, Evidence, Compare, What-If, Sequences, Ghost, Intelligence, Create/Trickster, cited theses, and Grey narration remain read-only investigation surfaces.
- Thesis publication remains tied to an existing A Bulls App account session, never a wallet, and still requires indexed citations.
- Grey keeps observed market facts separate from user claims and later 24-hour observations and does not issue right/wrong verdicts.
- Missing market, holder, replay, or resolution metrics stay unavailable/null rather than becoming zero.
- The provider budget hard stop remains in force; planet entry, observatory reads, watchlist rendering, Replay, and thesis views do not create provider fan-out.
- The Seeker/mobile renderer budget and native WebGL lifecycle were not increased or replaced by this work.

## Validation

The feature implementation was fully release-gated at commit `a32217d34bc4da42a94de2efc0658e0202df081f` after the taxonomy compatibility repairs. GitHub Actions run `34259742988` completed successfully with:

- release baseline verification,
- TypeScript check,
- the full repository test suite,
- production frontend build, and
- Intelligence Worker dry-run bundle.

The release guard has since been strengthened so future builds also fail if the approved Top 50 Traders/Watchlist destinations disappear, the token-planet/wallet-star contract is reversed, planet entry silently invokes the live QUERY path, token-system navigation gains passive provider fetching, honest-empty disclosures are removed, the observatory loses its bounded/sample disclosure or Fomo reference-only rule, or wallet-execution locks change. The final `main` commit must pass this same gate before publication.

Automatic Cloudflare deployment is not currently authorized from GitHub Actions because the repository lacks the required `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` Actions credentials. The deployment workflow fails at the credential preflight before install, migrations, Worker publication, frontend publication, or live checks, so that failure does **not** alter production.

## Deployment and physical-device acceptance still required

Publication must use `npm run deploy:all` from a current `main` checkout with the user's existing Wrangler login, unless the GitHub Actions Cloudflare credentials are configured. The command tests and bundles both Workers before applying migrations or publishing either Worker.

After publication, the Seeker browser remains the required physical acceptance gate because hosted CI cannot certify the actual Android GPU/WebGL lifecycle. Verify no black screen, native rotation/pinch recovery, token PLANETS across Solana/Pump/PONS, local wallet-STAR systems, token+wallet Watchlist persistence, the cached/empty Top 50 Trader Observatory state, and unchanged Replay/Evidence/Create behavior. Keep the previous Cloudflare deployment versions available until that device check passes.
